# tosa-interp

A Rust implementation of a TOSA (Tensor Operator Set Architecture) interpreter, designed for use as an IR interpreter in compiler toolchains with built-in statistics collection hooks.

## Architecture

```
┌─────────────────────────────────────────────────┐
│  Public API: run_graph(), Interpreter::run()     │
├─────────────────────────────────────────────────┤
│  Interpreter Engine (ready-list scheduler)       │
│  - Dataflow-driven execution                    │
│  - Recursive sub-block eval for control flow    │
├─────────────────────────────────────────────────┤
│  Op Dispatch (match on Op enum)                 │
├────────────┬────────────┬────────────┬──────────┤
│ conv       │ matmul     │ pool       │ fft      │
│ elementwise│ reduction  │ data_layout│ resize   │
│ type_conv  │ shape_ops  │ control_   │ data_    │
│            │            │ flow       │ nodes    │
├────────────┴────────────┴────────────┴──────────┤
│  Shared: accum (accumulators), quant (scaling), │
│  math (bit-exact expf), common (validation)     │
├─────────────────────────────────────────────────┤
│  IR Layer (owned types from FlatBuffer)          │
├─────────────────────────────────────────────────┤
│  FlatBuffers Deserialization (flatc --rust)      │
└─────────────────────────────────────────────────┘
```

- **Runtime shape**: All tensor shapes are dynamic `Vec<usize>` — no compile-time rank specialization
- **Dtype dispatch**: `TensorData` enum with per-element-type variants (BOOL, INT4–INT64, INT48, FP8 E4M3/E5M2, FP16, BF16, FP32)
- **Statistics hooks**: `InterpreterHook` trait allows composable collectors via `HookSet`

## Supported Operators

Every operator of the TOSA 1.1 draft that the tosa-tools reference model
(v2026.08.0) implements is supported, for every element type it supports,
except the MX (microscaling, block-scaled) extension operators and CUSTOM.
Each operator is verified bit for bit against the reference model.

See [docs/OPERATOR_STATUS.md](docs/OPERATOR_STATUS.md) for the per-operator
status, the types and edge cases tested, conformance results and an estimate
of coverage relative to the specification.

## Testing

### Conformance against the reference model

The primary test suite is `tests/conformance`: graphs, inputs and expected
outputs generated by the tosa-tools test generator and reference model.
Outputs must match bit for bit, and ERROR_IF cases (invalid graphs) must be
rejected. The checked-in suite samples every type signature, special-value
variant and ERROR_IF kind; the complete suites can be generated locally.

```powershell
# One-off setup: the tosa-tools wheel provides the generator, the
# reference model and flatc (used by build.rs).
uv venv .venv
uv pip install --python .venv tosa-tools

cargo test --release --test conformance

# Regenerate an operator's suite, or build its complete suite.
.venv\Scripts\python scripts\gen_conformance.py --op conv2d
.venv\Scripts\python scripts\gen_conformance.py --op conv2d --full
$env:TOSA_CONFORMANCE_DIR = "target\conformance-full"
cargo test --release --test conformance

# Refresh the status table in docs/OPERATOR_STATUS.md.
.venv\Scripts\python scripts\conformance_report.py
```

On Linux and macOS use `.venv/bin/python` instead.

### Other suites

- **Unit tests** (`cargo test --lib`): numeric helpers such as FP8 encoding,
  `expf` and fixed-point scaling.
- **Integration tests** (`tests/integration.rs`): small hand-built graphs and
  the statistics hooks.
- **Equivalence tests** (`tests/equivalence.rs`): earlier per-operator and
  small-network fixtures checked against the reference model.
- **Model tests** (`tests/model_tests.rs`): `.tosa` models converted from
  TensorFlow and TFLite.
## Usage

```rust
use tosa_interp::{run_graph, run_graph_with_hooks, Tensor, TensorData, HookSet, StatsCollector, FlopCounter};
use std::collections::HashMap;

// Load a .tosa file
let data = std::fs::read("model.tosa")?;

// Prepare inputs
let mut inputs = HashMap::new();
inputs.insert(
    "input_0".to_string(),
    Tensor::new("input_0".to_string(), vec![1, 224, 224, 3], TensorData::F32(vec![0.0; 150528])),
);

// Run with statistics collection
let mut hooks = HookSet::new();
hooks.add(StatsCollector::new());
hooks.add(FlopCounter::new());

let outputs = run_graph_with_hooks(&data, inputs, &mut hooks)?;
```

## Statistics Collection

The `InterpreterHook` trait enables pluggable analysis:

```rust
pub trait InterpreterHook {
    fn pre_op(&mut self, op: &OpInfo, inputs: &[&Tensor]) {}
    fn post_op(&mut self, op: &OpInfo, inputs: &[&Tensor], outputs: &[&Tensor]) {}
    fn on_tensor_alloc(&mut self, name: &str, shape: &[usize], dtype: DType, bytes: usize) {}
    fn on_tensor_free(&mut self, name: &str, bytes: usize) {}
}
```

Built-in collectors:
- **`StatsCollector`** — op counts, per-op timing, peak memory usage
- **`FlopCounter`** — estimated FLOPs for compute ops (MATMUL, CONV2D, element-wise)
- **`OpTrace`** — records every op execution with input/output shapes

Multiple collectors compose via `HookSet` or `Vec<Box<dyn InterpreterHook>>`.

## Spec Compliance Notes

- **Bit-exact arithmetic**: FP16/BF16/FP8 results are computed in FP32 and rounded to the type exactly where the reference model rounds; accumulators follow each operator's `acc_type`
- **Integer overflow**: wraps (the specification leaves the result unpredictable); division by zero and out-of-range shifts are errors
- **CAST float→int**: saturates, then rounds half to even
- **NaN handling**: `nan_mode` (PROPAGATE / IGNORE) is honoured by MAXIMUM, MINIMUM, CLAMP, MAX_POOL2D, ARGMAX, REDUCE_MAX and REDUCE_MIN
- **RESCALE**: single, double and inexact rounding, per-channel scaling, signed and unsigned inputs/outputs
- **Validation**: ERROR_IF conditions from the specification are checked and reported as errors; tensor rank is limited to 6 like the reference model
- **Control flow**: sub-blocks looked up by block or region name (TOSA 1.1 format)

## Dependencies

- `flatbuffers` — FlatBuffer deserialization (schema compiled at build time via `flatc`; set `FLATC` or install the tosa-tools wheel into `.venv`)
- `half` — F16/BF16 types with num-traits support
- `libm` — double-precision `erf`
- `thiserror` — Error type derivation
- `npyz`, `libtest-mimic`, `serde_json` — test fixtures and the conformance harness (dev-dependencies)
