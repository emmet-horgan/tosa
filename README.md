# tosa

A Rust toolkit for [TOSA](https://www.mlplatform.org/tosa/) (Tensor Operator
Set Architecture) graphs: a bit-exact interpreter that matches the TOSA
reference model, a graph IR with a builder and serializer, a framework for
lowering other model formats to TOSA, and a command-line tool.

## Crates

| Crate | Path | Contents |
|---|---|---|
| `tosa-ir` | `crates/tosa-ir` | The graph IR (`Graph`, `BasicBlock`, `Operator`, `OpAttribute`, `TensorDef`), reading and writing the TOSA flatbuffer format, `BlockBuilder` / `GraphBuilder` for constructing graphs, tensors and element types (INT4 to INT64, FP8, FP16, BF16, FP32), a text rendering, and a NumPy `.npy` reader and writer. |
| `tosa-interp` | `crates/tosa-interp` | The interpreter: every TOSA 1.1 operator the reference model implements (except the MX extension), verified bit for bit against it; execution plans, persistent variables, resource limits and statistics hooks. Convolutions keep the reference accumulation order while vectorizing across output channels; integer paths work on 32-bit operands without wider intermediates (MobileNet v1 runs in about 0.1 s float and 0.13 s uint8). |
| `tosa-convert` | `crates/tosa-convert` | The conversion framework (source graph model, frontends, lowering registry and driver, quantization and layout helpers, cleanup passes) and the TFLite and ONNX frontends (features `tflite` and `onnx`, on by default). |
| `tosa-cli` | `crates/tosa-cli` | The `tosa` binary: `run`, `dump`, `check`, `convert`, `frontends`. |

## Building and testing

Only a Rust toolchain (1.88 or later) is needed; it works the same on Windows,
Linux and macOS.

```sh
cargo build
cargo test
cargo run -p tosa-cli -- --help
```

`cargo test` runs every crate's unit tests, the interpreter's API and
mechanics tests, the IR round-trip test over every checked-in graph, the
conversion framework tests, and the checked-in conformance suite: over 3000
operator test cases and several small networks generated by the tosa-tools
reference model. See [docs/TESTING.md](docs/TESTING.md) for how the suites
are built, the comparison rules, how to regenerate cases with the reference
model (via [uv](https://docs.astral.sh/uv/) or any Python environment) and
what CI runs. [docs/OPERATOR_STATUS.md](docs/OPERATOR_STATUS.md) tracks
per-operator status and coverage.

### FlatBuffers bindings

The bindings for the TOSA schema (`crates/tosa-ir/schema/tosa.fbs`) and the
TFLite schema (`crates/tosa-convert/schema/tflite.fbs`) are generated by
`flatc` and checked in, so building the crates does not need `flatc`. After
changing a schema, regenerate them with:

```sh
cargo xtask codegen          # rewrite the bindings
cargo xtask codegen --check  # verify the checked-in file is up to date
```

The xtask uses an installed `flatc` (`$FLATC`, or `flatc` on `PATH`); nothing
is built from source. Its version must match the `flatbuffers` runtime in
`Cargo.toml` (25.12.19): install it from your package manager or the
prebuilt archives on the
[flatbuffers releases page](https://github.com/google/flatbuffers/releases/tag/v25.12.19),
as CI does. The same command regenerates the TFLite bindings in
`crates/tosa-convert`.

## Interpreter

```rust
use std::collections::HashMap;
use tosa_interp::{FlopCounter, HookSet, Interpreter, NoopHook, StatsCollector, Tensor, TensorData, run_graph_with_hooks};

let data = std::fs::read("model.tosa")?;

let mut inputs = HashMap::new();
inputs.insert(
    "input_0".to_string(),
    Tensor::new("input_0".to_string(), vec![1, 224, 224, 3], TensorData::F32(vec![0.0; 150528])),
);

// One-shot, with statistics collection.
let mut hooks = HookSet::new();
hooks.add(StatsCollector::new());
hooks.add(FlopCounter::new());
let outputs = run_graph_with_hooks(&data, inputs.clone(), &mut hooks)?;

// Or hold an Interpreter: the graph is validated once, variables persist
// between runs, and the execution plan is available.
let mut interp = Interpreter::from_flatbuffer(&data)?;
let outputs = interp.run(inputs, &mut NoopHook)?;
println!("{:?}", interp.plan("main").unwrap().order);
```

Inputs must be exactly the graph's declared inputs, with their declared
types and shapes; anything else is reported as `Error::MissingInput`,
`Error::UnknownInput` or `Error::InputMismatch` before the graph runs.
Errors raised while executing an operator are wrapped in `Error::Operator`
with the block name, operator index and operator name; nested control flow
nests the wrappers, and `Error::root_cause()` and
`Error::failing_operator()` unwrap them.

Design points:

- **Validation up front**: creating an `Interpreter` checks every block
  (undefined tensors, duplicate producers, dependency cycles, tensor ranks
  and sizes) and computes its `ExecutionPlan`: a topological order with
  program-order tie-breaking and the tensors to free after each operator.
- **Tensor lifetimes**: intermediate tensors are dropped after their last
  use, so memory use follows the live set rather than the sum of all
  intermediates, and the hooks' `on_tensor_free` is exact.
- **Persistent variables**: VARIABLE / VARIABLE_READ / VARIABLE_WRITE keep
  their values across `Interpreter::run` calls and execute in program order.
- **Resource limits**: a single tensor may not exceed
  `Interpreter::set_max_tensor_bytes` (16 GiB by default) and tensor sizes
  are computed with overflow checks, so corrupt graphs fail with an error
  rather than an allocation failure.
- **Runtime shapes**: tensor shapes are dynamic `Vec<usize>`; dtypes are
  dispatched through the `TensorData` enum.

### Statistics hooks

```rust
pub trait InterpreterHook {
    fn pre_op(&mut self, op: &OpInfo, inputs: &[&Tensor]) {}
    fn post_op(&mut self, op: &OpInfo, inputs: &[&Tensor], outputs: &[&Tensor]) {}
    fn on_tensor_alloc(&mut self, name: &str, shape: &[usize], dtype: DType, bytes: usize) {}
    fn on_tensor_free(&mut self, name: &str, bytes: usize) {}
}
```

`OpInfo` names the operator, its index, its block and its nesting depth;
operators inside COND_IF and WHILE_LOOP bodies are reported between the
`pre_op` and `post_op` of the control-flow operator. Built-in collectors:
`StatsCollector` (op counts, timing, peak and current memory), `FlopCounter`
(estimated FLOPs for compute operators) and `OpTrace` (every operator with
block, depth, shapes and timing). They compose via `HookSet`.

### Spec compliance notes

- **Supported operators**: every operator of the TOSA 1.1 draft that the
  tosa-tools reference model (v2026.08.0) implements, for every element type
  it supports, except the MX (microscaling) extension and CUSTOM. Each is
  verified against the reference model bit for bit, except the
  transcendental operators (EXP, LOG, POW, SIN, COS, TANH, SIGMOID, ERF,
  FFT2D, RFFT2D), which must be within a few ULPs because the reference
  model's own results depend on the host's C library.
- **Bit-exact arithmetic**: FP16/BF16/FP8 results are computed in FP32 and
  rounded to the type exactly where the reference model rounds; accumulators
  follow each operator's `acc_type`.
- **Portable results**: transcendental functions come from the pure-Rust
  `libm` crate (or a port of musl's `expf`), never the platform C library.
- **Integer overflow** wraps (the specification leaves the result
  unpredictable); division by zero and out-of-range shifts are errors.
- **CAST float to int** saturates, then rounds half to even.
- **NaN handling**: `nan_mode` (PROPAGATE / IGNORE) is honoured by MAXIMUM,
  MINIMUM, CLAMP, MAX_POOL2D, ARGMAX, REDUCE_MAX and REDUCE_MIN.
- **RESCALE**: single, double and inexact rounding, per-channel scaling,
  signed and unsigned inputs and outputs.
- **Validation**: ERROR_IF conditions from the specification are checked
  and reported as errors; tensor rank is limited to 6 like the reference
  model.

## Graph IR and builder

```rust
use tosa_ir::{BlockBuilder, DType, Graph, GraphBuilder, Op, OpAttribute, TensorData};

let mut b = BlockBuilder::new("main");
let x = b.input("x", DType::F32, &[1, 4]);
let one = b.constant("one", &[1, 1], TensorData::F32(vec![1.0]))?;
let y = b.op1(Op::Add, OpAttribute::None, &[&x, &one], DType::F32, &[1, 4], "y");
b.output(&y);
let graph = GraphBuilder::new(b.build()).build();

std::fs::write("plus_one.tosa", graph.to_flatbuffer()?)?;
println!("{graph}");                       // readable listing
assert_eq!(Graph::from_flatbuffer(&graph.to_flatbuffer()?)?, graph);
```

The IR is lossless for everything the reference model writes: every
checked-in test graph round-trips through parse, serialize and parse
unchanged.

## Converting models

`tosa-convert` lowers other formats to TOSA through per-format frontends and
per-operator lowerings, with shared quantization and layout helpers and
cleanup passes. The TFLite frontend converts float, int8 and uint8 models
(about 80 builtin operators): MobileNet v1, v2 and v3, EfficientNet-Lite,
DeepLab v3, SSD MobileNet v2 and BlazeFace convert and run bit-exact
against TFLite's reference kernels in their quantized forms and to float32
rounding in float. The ONNX frontend converts float and quantized (QLinear)
models with a hand-written protobuf reader, so no protobuf toolchain is
needed: MobileNetV2, ResNet, DenseNet, ShuffleNet, Inception, SqueezeNet,
EfficientNet-Lite4, super-resolution and style-transfer networks agree with
onnxruntime to float32 rounding, and the int8 MobileNetV2 and ResNet-50 are
bit-exact. All 25 models are benchmarked. ExecuTorch `.pte` is next. See
[docs/CONVERSION.md](docs/CONVERSION.md) for the design, the operator list,
how models are verified and how to add a frontend.

```sh
tosa convert model.tflite -o model.tosa
tosa convert model.tflite --analyze
tosa run model.tosa -i input=x.npy --stats
tosa dump model.tosa
tosa check model.tosa
```

Well-known models are fetched (pinned by hash) and recorded with their
native runtime by `uv run scripts/models.py`; then
`cargo test --release -p tosa-convert --test models` checks them,
`cargo bench -p tosa-convert` benchmarks them, and
`uv run --with tosa-tools==2026.8.0 scripts/runtime_matrix.py` produces the
cross-runtime error and timing matrix (native runtime, `tosa-interp`,
reference model).
